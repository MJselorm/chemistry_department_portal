# API Reference

This inventory was checked against the FastAPI OpenAPI document generated by the current application. It documents routes registered by `backend/app/main.py`; it does not prove that a live deployment is at the same revision. Unless specified otherwise, successful calls return HTTP 200. Validation errors commonly return 422.

## Conventions

- **Bearer**: `Authorization: Bearer <Firebase ID token>`. The backend verifies the token and resolves the caller's profile.
- **Admin**: database role `admin` or `super_admin`.
- **Super Admin + MFA**: role `super_admin` and a recent Firebase second-factor claim.
- **Public**: no authentication dependency on that handler. Frontend navigation visibility is not an API access check.
- A named Pydantic body/response model defines the shape; see the linked schema file. **Untyped** means no explicit response model is declared, so the handler's return value is authoritative. Upload bodies are multipart.
- `frontend2/client.js` is the shared HTTP helper and `frontend2/endpoints.js` centralizes most client route strings. Frontend caller files are listed by feature.

FastAPI's default interactive documentation routes are also enabled by the `FastAPI(...)` construction in `backend/app/main.py`: public `GET /openapi.json`, `GET /docs`, `GET /docs/oauth2-redirect`, and `GET /redoc`. They are framework-generated discovery UI/schema routes, not domain operations, and are not repeated in the operation tables below.

| Collection | List/detail | Create body | Update body |
|---|---|---|---|
| `/api/directory/departments` | Public `GET /{collection}` and `GET /{collection}/{record_id}` | Admin `POST`; `DepartmentCreate` | Admin `PATCH /{collection}/{record_id}`; `DepartmentUpdate` |
| `/api/directory/executives` | Same | `ExecutiveCreate` | `ExecutiveUpdate` |
| `/api/directory/class-representatives` | Same | `ClassRepresentativeCreate` | `ClassRepresentativeUpdate` |

| `/api/directory/committees` | Same | `CommitteeCreate` | `CommitteeUpdate` |

For each collection, list takes query `skip`, `limit`, `is_active` and returns 200 untyped; detail takes `record_id` and returns 200 untyped; create returns 201 untyped; update returns 200 untyped; delete is `DELETE /{collection}/{record_id}`, Admin-only, 204. ## Privacy requests

Implementation: `backend/app/routers/privacy.py`, `backend/app/services/privacy.py`; schemas: `backend/app/privacy_schemas.py`. Two route families are currently registered; their status vocabularies and response contracts differ.

| Method and route | Access; parameters/body | Success response |
|---|---|---|
| `POST /privacy/requests` | Bearer; `PrivacyRequestCreate` | 201 `PrivacyRequestOut` |
| `GET /privacy/requests` | Bearer; query `limit`, `offset` | 200 `PrivacyRequestPage` |
| `GET /privacy/export` | Bearer | 200 JSON attachment; handler-generated payload |
| `GET /admin/privacy/requests` | Admin; query `request_type`, `status`, `limit`, `offset` | 200 `PrivacyRequestAdminPage` |
| `GET /admin/privacy/requests/{request_id}` | Admin; path `request_id` | 200 `PrivacyRequestAdminOut` |
| `PATCH /admin/privacy/requests/{request_id}` | Admin; path `request_id`; `PrivacyRequestReview` | 200 `PrivacyRequestAdminOut` |
| `GET /api/privacy/requests/me` | Bearer | 200 `list[PrivacyRequestOut]` |
| `POST /api/privacy/requests/export` | Bearer | 201 `DataExportResponse` |
| `POST /api/privacy/requests/deletion` | Bearer; `AccountDeletionRequest` | 200 `PrivacyRequestOut` |
| `GET /api/privacy/admin/requests` | Admin; query `status`, `limit` | 200 `list[AdminPrivacyRequestOut]` |
| `PATCH /api/privacy/admin/requests/{request_id}` | Admin; path `request_id`; `PrivacyRequestUpdate` | 200 `AdminPrivacyRequestOut` |

The legacy family uses request statuses `pending`, `under_review`, `approved`, `rejected`; `PrivacyRequestCreate` accepts `request_type` (`data_export` or `account_deletion`) and optional `details` (up to 2,000 characters), while `PrivacyRequestReview` accepts `status` and optional `resolution_note`. The `/api/privacy` family uses `pending`, `in_review`, `completed`, `rejected`, `cancelled`; `AccountDeletionRequest` accepts optional `reason` (up to 1,000 characters), and `PrivacyRequestUpdate` accepts `status` and optional `resolution_note` (up to 2,000 characters). Neither workflow automatically deletes an account. The legacy family calls the privacy audit/rate-limit helpers; the newer `/api/privacy` handlers do not currently invoke those helpers, even though the frontend uses that family. The `/api` export returns `generated_at`, `request`, `account`, `notification_read_state[]`, `push_subscriptions[]`, and `privacy_requests[]`; the legacy JSON attachment returns `schema_version`, `generated_at`, `account`, notification read-status metadata, safe push-subscription metadata, privacy request summaries, and omissions. Frontend callers use `/api/privacy` from `frontend2/SettingsPage.jsx`, `PrivacyRequestModal.jsx`, and `AdminPrivacyRequestsPanel.jsx`; route strings are in `endpoints.js`.

## OpenAPI and contract verification

Generate the current OpenAPI document from `app.main:app` (for example via `/openapi.json` in a running local API) when adding or changing routes. The request/response model definitions remain the authoritative source for accepted fields, defaults, and validation; this reference intentionally avoids copying those fields into a second schema catalog.
